# Security

This document records the current threat model, the security properties the
server is trying to preserve, and the controls that are already enforced in
repo-owned code.

The project is a local MCP server that launches first-party QSPICE tooling on
files inside a caller-selected workspace. It is not a container sandbox, a
multi-tenant service, or a privilege boundary between hostile local users.

## Threat Model

The server treats these as the primary risks worth mitigating in repo-owned
code:

- path traversal or symlink-based access outside the configured workspace root
- persisted manifests or plan files that smuggle out-of-workspace artifact
  paths back into later read, write, or cleanup operations
- caller-provided CLI switches that override repo-managed outputs or introduce
  unaudited path-bearing arguments to QSPICE
- accidental deletion of files outside the intended artifact roots during
  resume, cleanup, or session-bundle lifecycle operations

The server does not currently try to defend against:

- a hostile local user who can already modify the workspace, interpreter, or
  configured executables
- kernel- or OS-level sandbox escapes from the QSPICE or QUX processes
- time-of-check/time-of-use races after validation on a filesystem controlled
  by another local actor

## Current Controls

### Workspace Confinement

- All repo-owned path resolution flows through workspace-aware helpers that
  reject resolved paths outside the configured root.
- Existing symlink hops in resolved path prefixes are collapsed before the
  workspace-root check, so a path that traverses an existing symlink outside
  the workspace is rejected.
- Services that require an existing input file also enforce expected suffixes
  before the underlying backend or companion executable is invoked.

### Persisted Artifact Safety

- Batch manifests, Monte Carlo plans, worst-case plans, and remote session
  summaries now stamp `schema_version`.
- Loaders for batch manifests and prepared statistical plans accept older
  versionless payloads as a narrow legacy path but reject unsupported future
  versions explicitly.
- Embedded paths loaded from persisted batch manifests and prepared plans are
  re-confined to the active workspace before later reads, writes, comparisons,
  or cleanup logic can use them.

### Process Invocation Guardrails

- The server controls simulation log and raw output locations instead of
  allowing callers to override them through raw QSPICE `-o` or `-r` switches.
- Main QSpice runs now preserve prior `.log` and `.qraw` artifacts by backing
  them up before launch and restoring them if the run times out or exits
  unsuccessfully.
- `extra_switches` now only accepts standalone dash-prefixed flags and rejects
  positional or path-like tokens so callers cannot smuggle ad hoc filesystem
  arguments through the QSPICE invocation surface.
- Audited writable artifact and bundle outputs now enforce explicit expected
  suffixes instead of silently rewriting or accepting mismatched file types.
- QPOST-backed measure refreshes now stage `.meas` output to temporary paths,
  promote it only after a successful refresh, and map refresh timeouts to
  stable domain errors.
- QUX-backed export helpers resolve their input and output paths inside the
  workspace before the companion process is launched, reject dash-prefixed
  export expressions that would be interpreted as switches, and map companion
  timeouts to stable domain errors.

### Cleanup Boundaries

- Remote-session bundle deletion only targets the staged bundle path stored for
  that session.
- Failed or timed-out QSpice runs discard partial replacement log/raw outputs
  and restore the previous artifacts when those paths already existed.
- Resume and retained-artifact cleanup flows operate on paths that were either
  generated by the current run or revalidated from persisted manifests inside
  the workspace.

## Operational Guidance

- Keep the configured workspace root as narrow as practical for the task.
- Treat persisted manifests and prepared plans as trusted only when they were
  created inside the current workspace by the same project version or an older
  compatible version.
- Avoid granting write access to the workspace root to unrelated processes
  while long-running simulations or cleanup flows are active.

## Remaining Hardening Work

- audit any newly added writable artifact surfaces so suffix enforcement stays
  explicit as the tool surface grows
- review future companion helpers for consistent timeout handling and cleanup
  on abrupt termination
- tighten timeout and partial-failure cleanup semantics where staged artifacts
  can still be left behind after abrupt process termination
