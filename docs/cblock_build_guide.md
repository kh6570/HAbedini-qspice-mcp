# C-Block (DLL) Build Guide

This guide covers how to compile a QSpice C-block custom device from the C++
scaffolds generated by `scaffold_dll_device` or `scaffold_dll_device_from_symbol`,
and how to recover when QSpice reports a missing `.DLL`.

## Prerequisites

### Required: C++ Compiler

QSpice C-block DLLs are standard 32-bit Windows DLLs compiled from C++ source.
You need **one** of the following:

| Toolchain | How to get it | Build command |
|---|---|---|
| **DMC (Digital Mars C++) — bundled with QSpice** | Installed with QSpice at `<install>/dm/bin/dmc.exe` (for example `C:\Program Files\QSPICE\dm\bin\`). QSpice GUI run (F5) can compile embedded C-blocks with this toolchain automatically. | `dmc -mn -WD my_device.cpp kernel32.lib` |
| **MSVC (Microsoft C/C++ compiler)** | Install Visual Studio 2022 Community (free) with the "Desktop development with C++" workload, or the standalone [Build Tools for Visual Studio](https://visualstudio.microsoft.com/downloads/#build-tools-for-visual-studio-2022) | `cl /LD /EHsc my_device.cpp /Femy_device.dll` |
| **Clang-cl (LLVM for Windows)** | Included with Visual Studio, or install LLVM separately | `clang-cl /LD /EHsc my_device.cpp /Femy_device.dll` |

**DMC limits:** the bundled compiler targets C++98-era code. Modern C++17/20 features
require MSVC or another external toolchain. MCP `build_dll_device` with `toolchain="auto"`
prefers bundled DMC when `QSPICE_EXE` is configured, then MSVC, then CMake.

### Required: Windows SDK

Both MSVC and Visual Studio Build Tools include the Windows SDK headers
(`windows.h`) needed by QSpice DLL entry points. If you installed only LLVM
without Visual Studio, you may need the standalone [Windows SDK](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/).

### Optional: CMake

A `CMakeLists.txt` is generated alongside the `.cpp` scaffold. CMake can
automate the build and is included with Visual Studio or available from
[cmake.org](https://cmake.org/download/).

```powershell
cmake -S my_device -B my_device/build
cmake --build my_device/build --config Release
```

## Building from the Scaffold

The scaffold tools (`scaffold_dll_device` and `scaffold_dll_device_from_symbol`)
generate a `.cpp` source file and a `CMakeLists.txt`. By default these are placed
next to your schematic so QSpice's "Show Source" command finds them automatically.

### Step-by-step (QSpice-bundled DMC)

1. Open a terminal in the directory containing the `.cpp` file.
2. Ensure `<QSPICE install>\dm\bin` is on `PATH` (or invoke `dmc.exe` by full path).
3. Run:
   ```
   dmc -mn -WD my_device.cpp kernel32.lib
   ```
4. The resulting `my_device.dll` appears beside the source file.

With qspice-mcp, `build_dll_device` or `write_workspace_text_file` (for `.cpp`)
can run this build when `QSPICE_EXE` points at your `QSPICE64.exe` install.

### Step-by-step (MSVC Developer Command Prompt)

1. Open **Developer Command Prompt for VS 2022** (or `x64 Native Tools Command Prompt`).
2. Navigate to the directory containing the generated `.cpp` file.
3. Run:
   ```
   cl /LD /EHsc my_device.cpp /Femy_device.dll
   ```
4. The resulting `my_device.dll` must be where QSpice can load it (see below).

### Step-by-step (CMake)

1. Open a terminal in the directory containing the scaffold files.
2. Run:
   ```
   cmake -S . -B build
   cmake --build build --config Release
   ```
3. The DLL is placed in `build/Release/` (or `build/` depending on config).

## Where to Place the DLL

QSpice searches for custom device DLLs in this order:

1. **The schematic directory** — simplest: put the `.dll` next to your `.qsch`.
2. **A directory on the system PATH** — for shared devices used across multiple projects.
3. **The QSpice installation directory** — typically `C:\Program Files\QSPICE\`.

For most workflows, placing the `.dll` next to the schematic is the right choice.

## QSpice Prompt Flow When DLL Is Missing

When QSpice encounters a DLL block (`.DLL` symbol) whose device file cannot
be found, the behavior depends on context:

| Scenario | QSpice behavior |
|---|---|
| **Open schematic** | QSpice may show a warning dialog: "Cannot find DLL device: my_device.dll". The schematic opens but the block is non-functional. |
| **Run simulation** | Error: "Can't find definition of subcircuit 'my_device'" or "Unresolved subcircuit". Simulation aborts. |
| **Show Source** (right-click > Show Source) | If the `.cpp` was placed next to the `.qsch`, QSpice opens it in an editor. If not found, nothing happens. |

### Typical error messages and their meanings

| Message | Likely cause | Action |
|---|---|---|
| `Can't find definition of subcircuit "my_device"` | DLL not built, or not in search path | Build the DLL and place it next to the `.qsch` |
| `Unresolved subcircuit` | Netlist references a bare device name with no matching `.dll` | Ensure the DLL block value matches the built DLL name |
| `Missing .DLL` | QSpice found the reference but the file is absent | Place the compiled `.dll` in the schematic directory or PATH |
| `X... my_c_block` in generated netlist | Clean-room netlist regeneration emitted a subcircuit call instead of DLL reference | Use the editor backend (install `qspice-mcp[backends]`) for DLL-based schematics, or fix the netlist manually |

## Fallback When External Build Tools Are Absent

If MSVC is not installed:

### Option 1: Use QSpice-bundled DMC (default for typical C-blocks)

A standard QSpice install already includes `dmc.exe`. Build from the schematic
directory with `dmc -mn -WD <device>.cpp kernel32.lib`, or use MCP
`build_dll_device` / `write_workspace_text_file` with `QSPICE_EXE` configured.

### Option 2: Use a pre-compiled DLL

If someone has already compiled the DLL, copy it next to your `.qsch` file.
QSpice does not require recompilation as long as the exported function names
match.

### Option 3: Install MSVC Build Tools

The **Build Tools for Visual Studio 2022** support modern C++ when DMC is too
limited. Use the "Developer Command Prompt" shortcut or `vcvars64.bat`.

### Option 4: Cross-compile from another machine

Build the DLL on any Windows machine with DMC or MSVC, then copy the `.dll`
to your target machine. QSpice DLLs have no external dependencies beyond
`windows.h` and the C runtime (universal on Windows).

## Troubleshooting

### DLL compiles but QSpice can't find it

- Verify the DLL filename matches the device name in the `.DLL` block's value field (case-sensitive).
- Check that the exported function name matches: `scaffold_dll_device_from_symbol` uses the device name as the export name. Run `dumpbin /EXPORTS my_device.dll` in a Developer Command Prompt to verify.
- Place the `.dll` in the same directory as the `.qsch` file.

### DLL compiles but simulation crashes

- Ensure all pin names in the schematic match the `data[index]` references in the C++ source.
- Run `validate_dll_symbol_signature` from the MCP toolset to cross-check the symbol against the source.
- The C++ entry point must be declared `extern "C" __declspec(dllexport)`.

### "Show Source" does nothing

- The `.cpp` file must be in the same directory as the `.qsch` file with a matching base name.
- Use `scaffold_dll_device` with `schematic_path` or `scaffold_dll_device_from_symbol` (which auto-places by default) to ensure correct placement.
